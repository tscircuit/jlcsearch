# Microcontroller USB audit: ranks 301–1000

Audited 2026-09-24. This completes the top 1,000 records by stock, extending the [first 100](microcontroller-usb-audit.md) and [next 200](microcontroller-usb-audit-next200.md). The production snapshot came from [workflow run 36062946901](https://github.com/tscircuit/jlcsearch/actions/runs/36062946901):

```sql
SELECT lcsc, mfr, stock, has_usb FROM microcontroller
ORDER BY stock DESC, lcsc ASC LIMIT 1000;
```

The first 300 records match the previous audit. This batch contains **290 Yes and 410 No**. Of its 290 USB-capable parts, 26 were already flagged correctly and **264 require correction from No to Yes**. Across all three batches: **1,000 distinct records, 387 Yes, 613 No, and 360 corrections** relative to their original snapshots.

## Evidence and interpretation

Each manifest row records the exact manufacturer part number, LCSC number, stock rank, previous flag, reviewed flag, source URL and evidence. Decisions use manufacturer specifications, manufacturer-authored datasheets (including distributor-hosted copies), and official device definitions:

- ST's pinned `STM32_open_pin_data` XML inventories establish the presence or absence of a hardware USB IP for 201 parts in this batch. Matching resolves the exact device variant, not just the family prefix. USB middleware and USB power-delivery IP are excluded. The earlier STM32 decisions were also cross-checked against these inventories where an exact definition was available, with no disagreements.
- Microchip's versioned device packs provide exact-device register inventories for PIC and AVR parts. USB control blocks such as `UCON`, `U1CON`, `USBCON` and `UDCON` establish hardware support. The manifest identifies the pack version and internal device file.
- Other records use exact product parameters, device selection tables, complete peripheral inventories, or pinned vendor SDK device headers. Shared sources cover package variants only when their interface inventory is the same.

“Has USB” means an integrated USB data controller/interface, including host, device, OTG and hub controllers. Controllers requiring an external PHY still qualify. USB power delivery alone, a USB programming adapter, USB-powered evaluation hardware, software-emulated USB download, and CRC16_USB do not qualify. No decisions come from reviewing the hardware inventory, not from missing supplier keywords. These checks establish documented silicon capability; they do not electrically test physical inventory.

## Important distinctions

- **STM32F303C8T6 / STM32F303K8T6:** no USB controller; USB-equipped F303 variants must not be generalized to these parts.
- **LPC1517JBD48E:** USB is absent in the manufacturer's ordering table; LPC1547 supports it.
- **MG32F02A032AD48:** no USB; do not inherit USB support from MG32F02A064.
- **STC32G8K48:** USB ISP is software-emulated; unlike STC32G12K128, it does not establish a hardware USB peripheral.
- **CH334H / CYUSB3304-68LTXC:** USB hub devices appear in this catalog category and have USB.
- **MT25QL256ABA8E12-1SIT:** SPI NOR flash appears in the microcontroller category and has no USB.
- **i.MX, Allwinner and Zynq application processors:** some appear in this category; their documented USB controllers qualify. Category assignments are unchanged.

## Migration and rebuild behavior

The manifest is `lib/db/derivedtables/microcontroller-usb-audit-next700.json`. Migration `0013_microcontroller_usb_next700.sql` updates only `has_usb`, matching normalized exact manufacturer part numbers. It can be reapplied safely. Migrations 0011 and 0012 remain unchanged. The same exact-part decisions take precedence over supplier metadata during future derived-table rebuilds.

```sh
bun scripts/generate-microcontroller-usb-migration.ts --next700
bun test tests/lib/microcontroller-usb.test.ts
```

Tests check complete, disjoint ranks 1–1000, every decision during import, conflicting supplier descriptions, family exceptions, and all three SQL migrations against 1,000 deliberately inverted flags. They also check repeated application, normalization, preservation of other fields, and isolation of unaudited parts and previously reviewed batches.
